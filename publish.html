Publishing guide

Publish an app to the registry

A CoolCloud app is a folder with a manifest.json and a web entry point. There is no build step, no bundler and no SDK to install: the app runs same-origin in a sandboxed frame and talks to the normal HTTP API with the signed-in session.

Before you start. Apps are code that people install on their own servers. Publish something you would run yourself, keep it small, and state which API endpoints it uses. The registry is a catalogue, not a security review.

1. Create the app folder

The smallest useful app is three files:

my-app/
├── manifest.json
├── README.md
└── web/
    └── index.html      # markup, styles and the app script

Split index.html into app.js and app.css if it grows. Relative paths work inside web/.

2. Write manifest.json

{
  "id": "acme:notes",
  "name": "Notes",
  "developer": "acme",
  "version": "1.2.0",
  "description": "Shared notes for the team, stored in Files.",
  "icon": "fa-solid fa-note-sticky",
  "accent": "editor",
  "category": "Productivity",
  "entry": "web/index.html",
  "permissions": ["storage"],
  "website": "https://acme.example/notes"
}
FieldRequiredNotes
idyesdeveloper:name, lowercase, unique in the registry
nameyesShown in the app drawer and settings
developeryesYour namespace; matches the id prefix
versionyesSemver. Bump it on every published change
descriptionyesOne sentence, under 140 characters
iconyesA Font Awesome class, for example fa-solid fa-cube
entryyesUsually web/index.html
permissionsnoOnly what the app truly needs: storage, files:read, …
accentnoAn app accent name: files, calendar, editor, …
categorynoOne of the registry categories, or a new one you propose
typenoapp (default) or widget for the home page

3. Build it like it belongs

Load the design system instead of inventing a second one:

<link rel="stylesheet" href="/vendor/fa/css/all.min.css" />
<link rel="stylesheet" href="/vendor/fonts/inter.css" />
<link rel="stylesheet" href="/css/tokens.css" />
<link rel="stylesheet" href="/css/base.css" />
<link rel="stylesheet" href="/css/components.css" />

The frame is same-origin, so fetch('/api/...', { credentials: 'same-origin' }) works and the session cookie comes along. Use the user's theme: 

try {
  document.documentElement.dataset.theme =
    window.parent.document.documentElement.dataset.theme || 'light';
} catch {
  /* opened outside CoolCloud */
}

4. Store app data the supported way

Declare "permissions": ["storage"]. The first run asks the user to allow storage; after that, read and write JSON under your own app id and the signed-in user: 

const read = await fetch('/api/apps/acme:notes/storage', { credentials: 'same-origin' });
const { data } = await read.json();

await fetch('/api/apps/acme:notes/storage', {
  method: 'PUT',
  credentials: 'same-origin',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ key: 'state', value: JSON.stringify({ notes: [] }) })
});

Values are capped at 200 KB each. A 403 with consentRequired means the user has not granted storage yet; show them a button and POST { "scopes": ["storage"] } to /api/apps/<id>/grants.

Files, calendar, mail and the rest are available through the normal endpoints when the user has access. Never assume more access than the signed-in user already has — the server enforces ACLs on every call.

5. Test it on a real instance

Install from the folder

coolcloud --install acme:notes dir=./my-app

Open it

It appears in All apps. Check light and dark, a narrow window, and the permission prompt.

Check the console

No errors, no requests to third-party hosts you did not disclose, and no secrets in web/.

6. Publish it

The official registry lists entries that point at a repository and the folder inside it. A pull request to openhcat/cc-appregistry that adds your entry to registry.json is the whole process. 

{
  "id": "acme:notes",
  "name": "Notes",
  "developer": "acme",
  "version": "1.2.0",
  "description": "Shared notes for the team, stored in Files.",
  "icon": "fa-solid fa-note-sticky",
  "accent": "editor",
  "category": "Productivity",
  "runtime": "external",
  "repo": "https://github.com/acme/coolcloud-notes.git",
  "path": ".",
  "files": ["manifest.json", "web/index.html", "README.md"],
  "tags": ["notes", "collaboration"]
}

path is the folder inside the repository that holds manifest.json. If you host the app inside a monorepo, point at the subfolder. files is the list the installer downloads when it cannot clone the repository; keep it complete.

Review checklist

  • The manifest id is unique and the version is bumped.
  • The app has a README that says what it stores and which endpoints it calls.
  • No API keys, tokens or private URLs anywhere under web/.
  • Permissions are minimal; storage is requested only if the app really stores data.
  • It works with the keyboard, at 360 px wide, and in both themes.
  • You have installed it from your own folder and used it end to end.
Your own registry is always allowed. Point Admin → App Store → Add registry at any JSON file with this shape — internal tools do not need to be published here.
